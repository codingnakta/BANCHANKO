## 1. 서비스 개요

### 1.1 한 줄 정의
반창고는 중·고등학교 담임교사와 학생을 위한 AI 기반 통합 학급관리 웹앱이다.

### 1.2 추진 배경
- 현재 학급 정보가 메신저, 종이 가정통신문, 학교 시스템, 구두 안내 등 여러 경로로 분산되어 학생이 필요한 정보를 찾기 어렵다.
- 담임교사는 공지 반복, 과제 일정 안내, 출결 기록, 일정 관리에 많은 시간을 사용한다.
- 반창고는 Supabase를 기반으로 학급 데이터를 통합 관리하고, 나이스 교육정보 개방 포털 API(시간표·급식·학교 정보)와 연계하며, Upstage Solar API와 AI 챗봇을 활용해 학급 운영과 학생의 자기관리 경험을 개선한다.
- 초기 출시에서는 반응형 웹과 이메일 로그인을 사용하고, 인앱 알림을 우선 제공한다.
- 개인정보와 학교 시스템 연계의 복잡성을 고려하여 외부 API 데이터는 자동 반영 후 교사가 확인·수정할 수 있는 구조로 설계한다.

### 1.3 제품 목표
- 공지사항, 과제 일정, 출결, 가정통신문, 시간표, 급식, 청소 당번, 학급 행사 등 학급생활에 필요한 정보를 한곳에서 제공한다.
- 담임교사는 반복적인 안내와 일정 관리 업무를 줄인다.
- 학생은 오늘 해야 할 일과 학급 일정을 스스로 확인하여 중요한 정보를 놓치지 않는다.
- AI 챗봇을 통해 학생이 자연어로 학급 일정, 과제, 공지, 급식, 청소 당번 등을 질문하고 즉시 답변을 받을 수 있다.

## 2. 문제 정의와 해결 방안

### 2.1 사용자 문제
- 담임교사는 공지, 과제 일정, 출결, 학급 행사와 학생별 안내를 여러 도구에서 관리해야 하며, 학생에게 최신 일정을 전달하기 어렵다.
- 학생은 시간표, 급식, 과제 일정, 청소 당번, 행사 등의 정보가 흩어져 있어 필요한 내용을 놓치거나 반복적으로 교사에게 질문한다.
- 학급 일정에 변경이 생겼을 때 최신 정보를 확인하기 어렵다.

### 2.2 해결 방안
- 교사가 학급 정보를 등록·수정하고 학생의 접근 권한을 관리할 수 있는 통합 학급 공간을 제공한다.
- 학생은 오늘의 일정, 과제 일정, 공지, 출결 관련 안내, 급식, 청소 당번을 한 화면에서 확인한다.
- 과제와 가정통신문에는 외부 자료 URL을 연결할 수 있다. 단, 서비스 내부 파일 업로드·다운로드, 학생의 파일 제출, 학생별 제출 현황 관리는 제공하지 않는다.
- AI 챗봇은 저장된 학급 데이터만 근거로 학생의 질문에 답하고, Upstage Solar API를 활용해 공지 요약과 오늘의 할 일을 생성한다.
- 초기 알림은 인앱 알림으로 제공한다.

### 2.3 차별점
- 일반 학교 행정 시스템이 공식 행정 처리 중심이라면, 반창고는 담임교사와 학생의 일상적인 학급생활 관리에 초점을 둔다.
- 시간표·급식·공지·과제 일정·청소 당번·행사를 하나의 학생용 화면과 대화형 AI 인터페이스로 연결하며, 학급 단위로 빠르게 설정하고 운영할 수 있다.
- AI가 임의로 답변하지 않도록 학급 데이터 기반 응답과 출처·최종 갱신 시각 표시를 적용한다.
- 자동 연동 데이터는 교사 확인 후 학생에게 공개하여 잘못된 시간표나 급식 정보로 인한 혼선을 줄인다.

## 3. 타겟 사용자와 이용 시나리오

### 3.1 타겟 사용자
주요 사용자는 중·고등학교 담임교사와 해당 학급 학생이다. 각 담임교사 계정은 하나의 학급만 만들고 관리하며, 학생 계정은 하나의 학급에만 소속된다.

| 역할 | 특성 |
|---|---|
| 담임교사 | 디지털 도구 사용에 익숙하지 않아도 공지·과제 일정·자료 링크·일정을 빠르게 등록하고 학생에게 안내해야 한다. |
| 학생 | 스마트폰이나 컴퓨터로 아침 등교 전, 수업 전, 알림 확인 시점, 방과 후에 접속하며, 긴 안내문보다 오늘 해야 할 일과 변경 사항을 빠르게 확인하기를 원한다. |
| 서비스 관리자 | 담임교사 계정을 승인하고 계정 상태를 관리한다. |

학생의 개인정보와 출결 정보는 본인 및 권한이 있는 교사만 접근할 수 있어야 하며, 학생 간에는 다른 학생의 민감한 정보가 노출되지 않아야 한다.

### 3.2 핵심 이용 시나리오
1. 서비스 관리자가 승인한 담임교사는 소속 학교를 검색해 선택하고 하나의 학급을 생성한 뒤, 학생을 초대하거나 등록하고 시간표, 청소 당번, 학급 규칙을 설정한다.
2. 학생은 하나의 학급에 소속되어 해당 학급의 공지, 과제 일정, 일정과 안내만 확인한다.
3. 교사는 공지사항·가정통신문·과제 일정을 작성하고 외부 자료 URL을 연결하며 대상, 공개일, 마감일을 지정한다.
4. 학생은 로그인 후 자신의 학급의 오늘 시간표, 급식, 청소 당번, 미확인 공지, 예정된 과제와 할 일을 한눈에 확인한다.
5. 학생은 공지와 가정통신문 내용을 확인한다. 과제 파일 제출과 학생별 제출 현황 관리는 제공하지 않는다.
6. 교사는 출결 상태와 사유를 기록하고 수정 이력을 남긴다.
7. 나이스 API에서 시간표·급식 정보를 가져오되, 교사는 변경·오류 여부를 검토한 후 학급에 공개한다.
8. 학생은 AI 챗봇에게 '오늘 과제는 뭐야?', '내일 청소 당번은 누구야?', '이번 주 행사와 준비물 알려줘'처럼 질문하고 자신의 학급 데이터에 기반한 답변을 받는다.
9. 새로운 공지, 임박한 과제 일정, 청소 당번, 학급 행사 등은 인앱 알림으로 확인한다.

### 4.1 화면 구조와 전역 탐색
로그인한 학생과 담임교사는 모든 주요 화면 하단의 탭바를 통해 네 개의 최상위 화면으로 이동한다. 탭 순서는 `홈 → 우리반 → 할일 → 더보기`로 고정하며, 현재 선택된 탭은 시각적으로 구분해 표시한다.

| 탭 | 역할 |
|---|---|
| 홈 | 오늘 시간표, 급식, 청소 당번, 미확인 공지, 예정 과제와 행사의 요약 및 우선 항목 표시 |
| 우리반 | (학생) 학급 규칙, 시간표, 급식, 청소 당번, 공지·과제·행사 목록 / (교사) 학생 관리, 학급 기본 정보, 안내 관리, 시간표·급식 검수, 출결 기록 메뉴 |
| 할일 | 마감 임박 과제 일정, 미확인 공지, 다가오는 행사, AI가 생성한 오늘 할 일 (원본 이동 경로 포함) |
| 더보기 | 알림 목록, 계정과 개인정보 관리, 서비스 안내 |

- 원본 상세 화면이나 작성·수정 화면에서는 하단 탭바를 표시하지 않는다.
- 우리반·더보기 화면의 메뉴는 사용자 역할에 따라 다르게 표시한다.
- 학생에게 출결 기록 관리와 학생 소속 관리 메뉴를 표시하지 않는다.

## 6. 성공 지표 (KPI)

초기 MVP의 핵심 지표는 다음과 같으며, 출시 초기에는 정량 목표를 실제 학급 운영 데이터로 측정한 뒤 조정한다.

| 영역 | 지표 |
|---|---|
| 온보딩 | 가입 후 학급 생성 및 학생 참여 완료율 |
| 활성도 | 주간 활성 학생 비율, 학생의 주간 재방문 횟수 |
| 콘텐츠 | 공지·과제 일정·학급 일정 등록 건수, 학생 확인율 |
| 핵심 화면·AI | 오늘의 정보 화면 조회율, AI 챗봇 질문 해결률 |
| 데이터 품질 | 시간표·급식·청소 당번·학급 일정 데이터의 최신성, 교사 수정 발생률 |
| 품질·만족도 | 교사·학생 만족도, AI 답변 오류 신고율, 주요 기능 오류율 |

## 7. 리스크와 대응 방안

### 7.1 개인정보 보호
- 학교·학생 개인정보와 출결 정보가 포함되므로 개인정보 보호, 접근 권한, 보관 기간, 삭제 정책을 명확히 한다.
- 학생 정보는 최소한으로 수집하고, 역할별 접근 제어와 감사 로그를 적용한다.
- 계정 탈퇴·비활성화 시 즉시 로그인을 차단하고, 30일의 철회 가능 기간이 지난 뒤 계정 식별 정보를 삭제한다.
- 학급 종료 또는 학생 탈퇴 후 출결 사유는 해당 학년도 종료일로부터 1년간 제한 보관한 뒤 삭제 또는 익명 처리한다.
- AI 질문·오류 신고·알림 기록은 생성일로부터 90일간 보관한 뒤 식별 정보를 삭제한다.
- 보관 중인 데이터는 해당 학급의 권한 있는 담임교사와 서비스 관리자만 접근할 수 있고, 삭제·익명 처리 이력은 1년간 감사 목적으로 보관한다.

### 7.2 외부 API 의존
- 나이스 API의 제공 범위·갱신 주기가 학교에 따라 다를 수 있으므로, API 장애 시 수동 입력과 마지막 정상 데이터 표시를 제공한다.
- 시간표를 나이스에 공개하지 않는 학교가 있어 조회 결과가 비어 있을 수 있다. 이 경우에도 교사가 수동으로 입력해 학급을 운영할 수 있어야 한다.
- 시간표 엔드포인트가 중학교와 고등학교로 분리되어 있으므로, 학급 생성 시 저장한 학교급에 따라 호출 대상을 분기한다.
- 자동 연동 정보가 잘못될 가능성이 있으므로 교사 검수와 수정 기능을 필수로 둔다.

### 7.3 AI 응답 신뢰성
- AI가 오래된 정보나 권한 없는 정보를 답변할 위험이 있으므로 답변 근거 데이터, 갱신 시각, 불확실성 안내를 표시한다.
- 학급 데이터 외의 질문에는 답변 범위를 제한한다.

### 7.4 개발 범위 관리
- 초기 버전에서 모바일 푸시·문자·이메일 알림까지 동시에 제공하면 개발 범위가 커지므로 인앱 알림부터 시작한다.
- 출결은 학교의 공식 행정 시스템을 대체하지 않도록 MVP에서는 담임교사의 기록·조회 보조 기능으로 정의한다.
