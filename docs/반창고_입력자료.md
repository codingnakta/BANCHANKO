## 0. 입력 자료 전체 지도

반창고에 들어가는 자료는 출처 기준으로 네 갈래다.

| 구분 | 출처 | 예시 | 담당 |
|---|---|---|---|
| A. 외부 연동 자료 | 나이스 교육정보 개방 포털 API | 학교 정보, 시간표, 급식 | 자동 수집 → 교사 검수 |
| B. 교사 입력 자료 | 담임교사가 직접 등록 | 학급 기본 정보, 학급 규칙, 청소 당번, 공지·가정통신문·과제, 학급 행사, 출결 | 교사 |
| C. 계정 자료 | 가입·초대 | 교사 계정, 학생 명단, 소속 학급 | 관리자·교사 |
| D. 개발용 자료 | 개발팀이 준비 | 목업 JSON, 예시 문서, AI 프롬프트·질문 세트, 알레르기 코드표 | 개발팀 |

## 1. 사전 준비물 (개발 착수 전)

| # | 항목 | 발급처 | 저장 위치 |
|---|---|---|---|
| 1 | 나이스 교육정보 개방 포털 인증키 | open.neis.go.kr 회원가입 → 인증키 신청 | `.env` 의 `NEIS_API_KEY` (서버 전용, `VITE_` 금지) |
| 2 | Upstage Solar API 키 | console.upstage.ai | `.env` 의 `UPSTAGE_API_KEY` (서버 전용) |
| 3 | Supabase 프로젝트 URL·publishable key | supabase.com 프로젝트 생성 | `.env` 의 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` |
| 4 | 테스트용 실제 학교 5곳 | 나이스 학교검색 결과 | 목업 시드 데이터 |
| 5 | 알레르기 유발 식품 코드표 (1~19) | 나이스 급식 응답 규격 | 상수 파일 |

> 나이스 API는 인증키 없이도 일일 소량 호출이 가능하지만, 개발 중에는 트래픽 제한(`ERROR-337`)에 걸리므로 키를 발급받아 쓴다.

## 2. A. 외부 연동 입력 자료 — 나이스 API 3종

공통 베이스 URL: `https://open.neis.go.kr/hub/{엔드포인트}`
공통 파라미터: `KEY`(인증키), `Type=json`, `pIndex`(페이지), `pSize`(건수)

### 2.1 학교 검색 — `schoolInfo`

학급 생성 시 학교를 고르는 단계에서 쓴다. **여기서 얻는 두 코드가 없으면 시간표·급식 연동 자체가 불가능**하다.

**요청 파라미터**

| 파라미터 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `SCHUL_NM` | ○ | 학교명 (부분 일치) | `한국중학교` |
| `ATPT_OFCDC_SC_CODE` | | 시도교육청코드로 좁힐 때 | `B10` |

**응답에서 저장할 필드**

| 나이스 필드 | 내부 저장명 | 설명 | 예시 |
|---|---|---|---|
| `ATPT_OFCDC_SC_CODE` | `officeCode` | 시도교육청코드 | `B10` (서울) |
| `SD_SCHUL_CODE` | `schoolCode` | 표준학교코드 | `7010084` |
| `SCHUL_NM` | `schoolName` | 학교명 | `한국중학교` |
| `SCHUL_KND_SC_NM` | `schoolLevel` | 학교급 — 시간표 엔드포인트 분기 기준 | `중학교` / `고등학교` |
| `ORG_RDNMA` | `address` | 도로명 주소 (검색 결과 구분용) | `서울특별시 ○○구 ...` |

**입력 예시 (학급에 저장되는 학교 정보)**

```json
{
  "officeCode": "B10",
  "schoolCode": "7010084",
  "schoolName": "한국중학교",
  "schoolLevel": "중학교",
  "address": "서울특별시 성동구 ○○로 12"
}
```

### 2.2 시간표 — `misTimetable`(중학교) / `hisTimetable`(고등학교)

> 학교급에 따라 **엔드포인트가 분리**되어 있다. 학급에 저장한 `schoolLevel` 로 분기한다.

**요청 파라미터**

| 파라미터 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `ATPT_OFCDC_SC_CODE` | ○ | 시도교육청코드 | `B10` |
| `SD_SCHUL_CODE` | ○ | 표준학교코드 | `7010084` |
| `AY` | ○ | 학년도 | `2026` |
| `SEM` | ○ | 학기 | `2` |
| `GRADE` | ○ | 학년 | `2` |
| `CLASS_NM` | ○ | 반 | `3` |
| `ALL_TI_YMD` | | 특정 일자 | `20260901` |
| `TI_FROM_YMD` / `TI_TO_YMD` | | 기간 조회 (주간 시간표용) | `20260831` / `20260904` |

**응답에서 쓸 필드**

| 나이스 필드 | 내부 매핑 (`TimetableEntry`) | 예시 |
|---|---|---|
| `ALL_TI_YMD` | 조회 일자 | `20260901` |
| `PERIO` | `period` | `3` |
| `ITRT_CNTNT` | `subject` | `수학` |
| `GRADE` / `CLASS_NM` | 학급 검증용 | `2` / `3` |

**입력 예시 (하루치 시간표 · 검수 대기 상태)**

```json
{
  "sourceType": "timetable",
  "date": "2026-09-01",
  "reviewStatus": "pending",
  "syncedAt": "2026-08-31T22:00:00+09:00",
  "entries": [
    { "period": 1, "subject": "국어" },
    { "period": 2, "subject": "수학" },
    { "period": 3, "subject": "영어" },
    { "period": 4, "subject": "과학" },
    { "period": 5, "subject": "체육", "room": "체육관" },
    { "period": 6, "subject": "역사" },
    { "period": 7, "subject": "창의적체험활동" }
  ]
}
```

**반드시 준비해야 할 예외 케이스 자료**
- 시간표를 나이스에 공개하지 않는 학교 → 응답 `INFO-200`(데이터 없음). 이 경우 **교사 수동 입력용 빈 시간표 템플릿**이 필요하다.
- 교사·교실 정보는 나이스 응답에 없으므로 `teacher`, `room` 은 교사가 직접 채우는 값이다.

### 2.3 급식 — `mealServiceDietInfo`

**요청 파라미터**

| 파라미터 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `ATPT_OFCDC_SC_CODE` | ○ | 시도교육청코드 | `B10` |
| `SD_SCHUL_CODE` | ○ | 표준학교코드 | `7010084` |
| `MLSV_YMD` | | 특정 일자 | `20260901` |
| `MLSV_FROM_YMD` / `MLSV_TO_YMD` | | 기간 조회 (주간 급식용) | `20260831` / `20260904` |

**응답에서 쓸 필드**

| 나이스 필드 | 내부 매핑 (`MealMenu`) | 비고 |
|---|---|---|
| `MLSV_YMD` | `date` | `20260901` → `2026-09-01` 변환 필요 |
| `MMEAL_SC_NM` | 식사 구분 | `조식` / `중식` / `석식` — MVP는 **중식만** 사용 |
| `DDISH_NM` | `items` | `<br/>` 로 구분된 한 덩어리 문자열. 분리 + 알레르기 번호 파싱 필요 |
| `CAL_INFO` | (선택) 열량 | `652.5 Kcal` |
| `ORPLC_INFO` | (선택) 원산지 | 가정통신문성 정보 |

**원본 `DDISH_NM` 예시**

```
찰현미밥<br/>참치김치찌개 (1.5.9.13.)<br/>돈육장조림 (5.6.10.13.)<br/>구운계란 (1.)<br/>배추김치 (9.13.)<br/>요구르트 (2.)
```

**파싱 후 입력 예시 (`MealMenu`)**

```json
{
  "id": "meal-20260901",
  "date": "2026-09-01",
  "items": [
    { "name": "찰현미밥", "allergens": [] },
    { "name": "참치김치찌개", "allergens": [1, 5, 9, 13] },
    { "name": "돈육장조림", "allergens": [5, 6, 10, 13] },
    { "name": "구운계란", "allergens": [1] },
    { "name": "배추김치", "allergens": [9, 13] },
    { "name": "요구르트", "allergens": [2] }
  ],
  "calorie": "652.5 Kcal",
  "syncedAt": "2026-08-31T22:00:00+09:00"
}
```

| 번호 | 식품 | 번호 | 식품 | 번호 | 식품 |
|---|---|---|---|---|---|
| 1 | 난류 | 8 | 게 | 15 | 닭고기 |
| 2 | 우유 | 9 | 새우 | 16 | 쇠고기 |
| 3 | 메밀 | 10 | 돼지고기 | 17 | 오징어 |
| 4 | 땅콩 | 11 | 복숭아 | 18 | 조개류(굴·전복·홍합 포함) |
| 5 | 대두 | 12 | 토마토 | 19 | 잣 |
| 6 | 밀 | 13 | 아황산류 | | |
| 7 | 고등어 | 14 | 호두 | | |

> 코드표와 응답 필드명은 실제 호출 결과와 한 번 대조해 확정할 것.

### 2.4 나이스 API 에러 응답 자료

목업과 에러 처리 UI에 필요한 입력 자료다.

| 코드 | 의미 | 앱 동작 |
|---|---|---|
| `INFO-000` | 정상 | 검수 대기 상태로 저장 |
| `INFO-200` | 해당하는 데이터 없음 | "시간표 미공개 학교" 안내 + 수동 입력 유도 |
| `INFO-300` | 인증키 없음/오류 | 관리자 알림, 마지막 정상 데이터 표시 |
| `ERROR-300` | 필수값 누락 | 개발 오류. 요청 파라미터 점검 |
| `ERROR-337` | 일일 트래픽 초과 | 마지막 정상 데이터 표시 + `syncedAt` 노출 |
| `ERROR-500/600/601` | 서버·DB 오류 | 마지막 정상 데이터 표시 + 재시도 |

## 3. B. 교사 입력 자료 (수동 등록)

### 3.1 학급 기본 정보

| 항목 | 필수 | 예시 |
|---|---|---|
| 학급명 | ○ | `2학년 3반` |
| 학교 (2.1 결과) | | 한국중학교 / B10 / 7010084 / 중학교 |
| 학년 · 반 | ○ | `2` · `3` |
| 학년도 · 학기 | ○ | `2026` · `2` |

### 3.2 학급 규칙

자유 텍스트 목록. 예시 시드:

```json
[
  "등교 시간은 8시 40분까지입니다.",
  "휴대폰은 1교시 전 사물함에 보관합니다.",
  "결석·지각 시 당일 아침 담임에게 알립니다.",
  "청소 당번은 종례 후 15분간 담당 구역을 정리합니다.",
  "교실 내 음식물 반입을 금지합니다."
]
```

### 3.3 청소 당번 (`CleaningDuty`)

구역 × 담당 학생 명단. 요일별 로테이션이 필요하면 요일 필드를 추가한다.

```json
[
  { "id": "duty-1", "area": "교실 바닥", "studentNames": ["김민준", "이서연"] },
  { "id": "duty-2", "area": "칠판·교탁", "studentNames": ["박지호"] },
  { "id": "duty-3", "area": "복도·창가", "studentNames": ["최유나", "정하람"] },
  { "id": "duty-4", "area": "분리수거", "studentNames": ["강도윤"] }
]
```

### 3.4 학급 행사·일정 (`ClassEvent`)

```json
[
  { "id": "evt-1", "title": "2학기 중간고사", "startAt": "2026-10-13T09:00:00+09:00", "description": "1~4교시 시험, 5교시 후 하교", "isPublic": true },
  { "id": "evt-2", "title": "체육대회", "startAt": "2026-09-25T09:00:00+09:00", "description": "체육복·모자·물통 준비", "isPublic": true },
  { "id": "evt-3", "title": "학부모 상담 주간", "startAt": "2026-09-14T14:00:00+09:00", "isPublic": false }
]
```

### 3.5 출결 기록 (`Attendance`)

| 필드 | 값 |
|---|---|
| 상태 | `present` / `absent` / `late` / `early_leave` / `excused` |
| 사유 | 자유 텍스트 (민감정보 — 본인·담임만 조회) |
| 이력 | 변경 전후 값, 수정자, 수정 시각 |

```json
{
  "id": "att-1",
  "studentId": "stu-003",
  "date": "2026-09-01",
  "status": "late",
  "reason": "병원 진료",
  "history": [
    { "before": "absent", "after": "late", "editedBy": "김선생", "editedAt": "2026-09-01T10:12:00+09:00" }
  ]
}
```

## 4. C. 계정·명단 자료

### 4.1 학생 명단 (초대·등록용 CSV)

교사가 학기 초에 한 번에 넣는 자료. CSV 업로드가 아니라면 같은 항목을 폼으로 받는다.

```csv
번호,이름,이메일
1,김민준,minjun.kim@example.com
2,이서연,seoyeon.lee@example.com
3,박지호,jiho.park@example.com
4,최유나,yuna.choi@example.com
5,강도윤,doyun.kang@example.com
```

> 수집 항목은 **최소화**한다(기획서 7.1). 생년월일·연락처·주소는 MVP에서 수집하지 않는다.

### 4.2 계정 시드 (개발용)

| 역할 | 이메일 | 상태 | 비고 |
|---|---|---|---|
| 서비스 관리자 | `admin@banchango.test` | active | 교사 승인 처리 |
| 담임교사(승인됨) | `teacher@banchango.test` | active / approved | 2학년 3반 |
| 담임교사(승인대기) | `teacher.pending@banchango.test` | active / pending | 승인 대기 화면 확인용 |
| 학생 | `student1@banchango.test` ~ `student5@` | active | 2학년 3반 소속 |
| 비활성 학생 | `student.suspended@banchango.test` | suspended | 로그인 차단 확인용 |

## 5. D. 예시 문서 — 공지·가정통신문·과제

`Notice` 한 타입에 `type` 으로 3종을 구분한다. 각 유형별 예시 문서를 최소 1건씩 준비한다.

### 5.1 공지사항 (`type: "notice"`)

```json
{
  "id": "ntc-1",
  "type": "notice",
  "title": "9월 1일 개학식 안내",
  "body": "9월 1일(화) 개학식은 8시 50분 강당에서 진행합니다.\n- 등교 시간: 8시 40분까지 교실\n- 복장: 하복 또는 생활복\n- 준비물: 필기구, 여름방학 과제\n개학식 후 4교시까지 수업하고 급식 후 하교합니다.",
  "status": "published",
  "publishedAt": "2026-08-28T09:00:00+09:00"
}
```

### 5.2 가정통신문 (`type: "newsletter"`)

원문 PDF는 **서비스에 올리지 않고 외부 URL로 연결**한다(MVP 범위 제외 사항).

```json
{
  "id": "ntc-2",
  "type": "newsletter",
  "title": "[가정통신문] 2학기 방과후학교 수강 신청 안내",
  "body": "2학기 방과후학교 수강 신청을 아래와 같이 받습니다.\n\n1. 신청 기간: 9월 2일(수) ~ 9월 8일(화)\n2. 신청 방법: 아래 링크의 온라인 신청서 제출\n3. 개설 강좌: 수학심화, 영어회화, 코딩, 밴드\n4. 수강료: 강좌별 상이 (안내문 참조)\n\n문의: 담임교사 또는 교무실",
  "externalUrl": "https://school.example.kr/notice/2026/afterschool.pdf",
  "status": "published",
  "publishedAt": "2026-09-01T16:00:00+09:00"
}
```

### 5.3 과제 일정 (`type: "assignment"`)

파일 제출·제출 현황은 제공하지 않으므로 **마감일과 안내 문구, 참고 URL**만 들어간다.

```json
{
  "id": "ntc-3",
  "type": "assignment",
  "title": "국어 - 독서 감상문 제출",

## 6. AI 입력 자료 (Upstage Solar)

### 6.1 챗봇에 넣는 컨텍스트 번들

AI는 **저장된 학급 데이터만** 근거로 답한다. 질문 시 아래 묶음을 컨텍스트로 조립해 넣는다.

| 블록 | 내용 | 범위 |
|---|---|---|
| 학급 정보 | 학급명, 학년·반, 오늘 날짜·요일 | 항상 |
| 시간표 | 공개 승인된 오늘·이번 주 시간표 | `reviewStatus: published` 만 |
| 급식 | 공개 승인된 급식 + `syncedAt` | `published` 만 |
| 청소 당번 | 구역별 담당 학생 | 전체 |
| 안내 | `published` 상태의 공지·가정통신문·과제(제목·요약·마감일) | 공개일 지난 것만 |
| 행사 | `isPublic: true` 인 예정 행사 | 공개 일정만 |
| 제외 | **출결 기록, 다른 학생 개인정보, 비공개 일정, 검수 전 연동 데이터** | 컨텍스트에 넣지 않음 |

### 6.2 답변에 함께 실을 자료

- 근거 데이터 종류 (예: "시간표", "9월 1일 공지")
- 최종 갱신 시각 (`syncedAt` / `publishedAt`)
- 근거 부족 시 문구: "학급에 등록된 정보에서 확인할 수 없습니다."

### 6.3 테스트 질문 세트 (챗봇 검증용 입력 자료)

| # | 질문 | 기대 근거 | 기대 동작 |
|---|---|---|---|
| 1 | 오늘 과제는 뭐야? | 과제 목록 | 마감 임박순 답변 |
| 2 | 내일 청소 당번은 누구야? | 청소 당번 | 구역·이름 |
| 3 | 이번 주 행사와 준비물 알려줘 | 행사 + 공지 본문 | 준비물은 본문 인용 |
| 4 | 오늘 급식 뭐 나와? | 급식 | 갱신 시각 함께 표시 |
| 5 | 3교시 무슨 수업이야? | 시간표 | 공개된 시간표만 |
| 6 | 김민준 결석했어? | — | **답변 거부** (권한 밖) |
| 7 | 수학 숙제 대신 풀어줘 | — | **범위 제한 안내** |
| 8 | 다음 주 급식 알려줘 | 미수집 데이터 | 근거 없음 안내 |

### 6.4 "오늘 할 일" 생성 입력

`할일` 탭의 AI 생성 항목에 넣는 자료: 마감 3일 이내 과제 + 미확인 공지 + 7일 이내 행사 + 오늘 청소 당번. 각 항목은 원본 이동 경로(`linkTo`)를 반드시 포함한다.

## 7. 목업 파일 배치 제안

Supabase 연동 전 화면 개발에 쓸 시드 데이터 위치.

```
src/mocks/
├── school.json          # 2.1 학교 정보

├── events.json          # 3.4 학급 행사
├── attendance.json      # 3.5 출결 + 이력

    ├── misTimetable.sample.json

`src/constants/` 에 추가할 상수 자료: 알레르기 코드표(19종), 교시 시간 매핑(1교시 09:00~09:45 …), 출결 상태 라벨, 알림 유형 라벨.
