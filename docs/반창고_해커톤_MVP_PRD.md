# 반창고 — 해커톤 제출용 MVP PRD

> 해커톤 시간 안에 **실제로 동작하는 데모**를 완성하는 것을 목표로, 전체 기획(`반창고_기획서.md`)에서 핵심 흐름만 남긴 축소판 PRD입니다.
> 이 문서 하나를 AI 개발 도구(Claude Code 등)에 전달하면 바로 개발을 시작할 수 있도록 작성했습니다.

---

# 1. 서비스 개요

- **서비스명**: 반창고 (BANCHANKO)
- **한 줄 설명**: 담임교사가 올린 공지·과제와 나이스 시간표·급식을 학생이 한 화면에서 확인하고, AI 챗봇에게 물어볼 수 있는 학급관리 웹앱
- **해결하려는 문제**: 학급 정보(공지, 과제, 시간표, 급식)가 메신저·종이·구두 안내로 흩어져 있어 학생이 놓치고, 교사는 같은 안내를 반복한다
- **핵심 사용자**: 중·고등학교 담임교사와 해당 학급 학생
- **주요 사용 상황**: 교사는 조회·종례 전후에 공지를 등록하고, 1인1역 과목도우미 학생이 수업 후 그 과목의 과제를 입력하며, 학생은 등교 전·쉬는 시간에 오늘의 학급 정보를 확인하거나 챗봇에게 질문한다

---

# 2. 문제 정의

- **현재 방식**: 공지는 메신저 단체방, 과제는 구두 안내, 시간표·급식은 별도 앱이나 게시판으로 각각 확인한다
- **현재 방식의 문제**: 정보가 흩어져 있어 학생이 놓치기 쉽고, 놓친 학생이 교사에게 반복 질문하며, 교사는 같은 안내를 여러 번 한다. 특히 중등은 교과 담임제라 담임교사가 과목별 과제와 마감일을 모두 알 수 없다
- **해결하려는 핵심 문제**: "우리 반의 오늘 정보"를 한 곳에서 볼 수 있게 하고, 궁금한 것은 AI에게 바로 물어볼 수 있게 한다
- **기대 효과**: 학생은 앱 하나로 오늘 할 일을 파악하고, 교사는 반복 안내 부담이 줄어든다

---

# 3. 사용자 시나리오

**교사 (데모 시나리오 1)**

이메일 회원가입 (역할: 교사)
→ 학교 검색·선택 (나이스 학교 검색 API)
→ 학급 생성 (학년·반 입력, 초대코드 자동 발급)
→ 공지 작성 ("금요일 체육대회, 체육복 지참")
→ (학생 참여 후) 과목도우미 지정 ("수학 도우미: 김민준")

**과목도우미 학생 (데모 시나리오 2)**

이메일 회원가입 (역할: 학생)
→ 초대코드 입력 → 학급 참여
→ 수학 수업 후, 과제 입력 ("수학 익힘책 32~35p", 마감일 지정)

**일반 학생 (데모 시나리오 3)**

초대코드 입력 → 학급 참여
→ 홈 화면에서 오늘 시간표·급식·새 공지·마감 임박 과제 확인
→ 공지 카드 탭 → 상세 내용 확인
→ 챗봇 탭 → "이번 주 과제 뭐 있어?" 질문 → 학급 데이터 기반 답변 확인

# 4. 핵심 기능

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| M1 | 이메일 로그인 | Supabase Auth 이메일 가입·로그인. 가입 시 교사/학생 역할 선택 | Must |
| M2 | 학급 생성 | 교사가 나이스 학교 검색 API로 학교를 선택하고 학년·반을 입력해 학급 1개 생성. 6자리 초대코드 자동 발급 | Must |
| M3 | 초대코드 참여 | 학생이 초대코드를 입력하면 해당 학급에 소속됨 (학생 1명 = 학급 1개) | Must |
| M4 | 공지 등록 | 교사가 제목·내용·외부 링크 URL을 등록·수정·삭제 | Must |
| M5 | 과목도우미 지정 | 교사가 우리반에서 학생에게 담당 과목을 지정 (1인 1과목, 해제 가능) | Must |
| M6 | 과제 등록 | 과목도우미 학생이 담당 과목의 과제(제목·내용·마감일)를 등록·수정·삭제. 교사는 모든 과제를 등록·삭제 가능 | Must |
| M7 | 오늘의 홈 화면 | 학생·교사가 오늘 시간표, 오늘 급식, 최근 공지, 마감 임박 과제를 카드로 확인 | Must |
| M8 | 나이스 시간표·급식 | 학급의 학교코드로 나이스 API를 조회해 오늘 시간표·급식을 자동 표시 (교사 검수 단계 없이 바로 표시) | Must |
| M9 | AI 챗봇 | 학생이 자연어로 질문하면 자기 학급의 공지·과제·시간표·급식 데이터만 근거로 답변 | Must |
| S1 | 청소 당번 | 교사가 요일별 당번을 입력하면 홈에 오늘 당번 표시 | Should |
| S2 | 시간표 수동 입력 | 나이스에 시간표를 제공하지 않는 학교를 위한 교사 직접 입력 | Should |
| C1 | AI 오늘 할 일 요약 | 홈 상단에 오늘 할 일을 AI가 한 문단으로 요약 | Could |

**이번 MVP에서 의도적으로 뺀 것** (전체 기획에는 있으나 데모에 불필요): 서비스 관리자·교사 승인, 출결 기록, 가정통신문, 외부 연동 데이터 검수·공개 워크플로, 인앱 알림, 계정 탈퇴·개인정보 보관 정책, 파일 업로드·제출 관리 — 10. MVP 범위 참고.

# 5. 화면 구성

하단 탭 3개: **홈 · 우리반 · 챗봇** (전체 기획의 4탭 중 할일·더보기 탭은 제외. 작성·상세 화면에서는 탭바 숨김)

### 5.1 로그인 / 회원가입
- **목적**: 계정 생성과 역할(교사/학생) 구분
- **구성**: 이메일·비밀번호 입력, 역할 선택(가입 시), 로그인 버튼
- **행동**: 가입, 로그인. 로그인 후 학급이 없으면 → 교사는 학급 생성 화면, 학생은 초대코드 화면으로 이동

### 5.2 학급 생성 (교사 전용)
- **목적**: 학교 선택과 학급 개설
- **구성**: 학교 이름 검색창(나이스 학교 검색 결과 목록), 학년·반 입력, 생성 버튼
- **행동**: 학교 검색·선택, 학급 생성. 생성 완료 시 초대코드를 크게 표시(복사 버튼)

### 5.3 초대코드 입력 (학생 전용)
- **목적**: 학급 참여
- **구성**: 6자리 코드 입력창, 참여 버튼
- **행동**: 코드 입력 → 학급명 확인 → 참여

### 5.4 홈 (메인)
- **목적**: 오늘의 학급 정보 요약
- **구성**: 오늘 날짜·학급명 헤더, 오늘 시간표 카드, 오늘 급식 카드, 최근 공지 목록(3개), 마감 임박 과제 목록, (Should) 오늘 청소 당번
- **행동**: 각 카드 탭 → 상세 화면으로 이동

### 5.5 우리반
- **목적**: 공지·과제 전체 목록과 관리
- **구성**: 공지/과제 탭 전환, 목록, 작성 플로팅 버튼(교사와 과목도우미에게만 표시), (교사만) 학생 목록·과목도우미 지정 메뉴
- **행동**: 목록 조회, 상세 보기, (교사) 공지 작성·도우미 지정, (도우미) 담당 과목 과제 작성

### 5.6 공지·과제 작성
- **목적**: 안내 등록. 공지는 교사만, 과제는 교사와 과목도우미만 작성 가능
- **구성**: 유형 선택(공지/과제 — 도우미는 과제로 고정), 과목(과제만 — 도우미는 담당 과목으로 고정), 제목, 내용, 마감일(과제), 외부 링크 URL(선택), 등록 버튼
- **행동**: 작성·등록. 과제 카드에는 작성한 도우미 이름이 표시됨

### 5.7 챗봇
- **목적**: 학급 데이터 기반 자연어 질의응답
- **구성**: 대화 목록, 입력창, 추천 질문 칩("오늘 급식 뭐야?", "이번 주 과제 알려줘")
- **행동**: 질문 입력 → AI 답변 확인

# 6. 입력 → 처리 → 결과

## 입력
- 교사: 학교 이름, 학년·반, 공지(제목·내용·링크), 과목도우미 지정(학생·담당 과목)
- 과목도우미 학생: 담당 과목의 과제(제목·내용·마감일·링크)
- 학생: 초대코드, 챗봇 질문(자연어)
- 외부: 나이스 API의 학교 정보·시간표·급식 데이터

## 처리
- 학급 생성 시 나이스 학교 검색 결과에서 시도교육청코드·표준학교코드·학교급을 저장한다
- 홈 화면 진입 시 저장된 학교코드로 나이스 시간표(중학교 `misTimetable` / 고등학교 `hisTimetable` 분기)·급식(`mealServiceDietInfo`)을 조회한다
- 챗봇 질문 시 해당 학급의 공지·과제 목록과 오늘 시간표·급식을 컨텍스트로 묶어 Upstage Solar API에 전달하고, "이 데이터에 없는 내용은 모른다고 답하라"는 시스템 프롬프트를 적용한다
- 모든 데이터 조회는 자기 학급 것만 가능하도록 Supabase RLS로 제한한다
- 작성 권한도 RLS로 강제한다: 공지는 해당 학급 교사만, 과제는 교사 또는 과목도우미로 지정된 학생만 등록할 수 있다

## 결과
- 학생 홈에 오늘 시간표·급식·공지·임박 과제가 카드로 표시된다
- 챗봇이 학급 데이터에 근거한 답변을 반환한다 (근거 없는 질문에는 "학급 정보에 없어요"로 응답)

# 7. 데이터 (Supabase)

| 테이블 | 주요 필드 | 설명 |
|---|---|---|
| `profiles` | id(auth.users FK), role('teacher'/'student'), name | 가입 시 자동 생성 |
| `classrooms` | id, teacher_id, name, office_code, school_code, school_level('middle'/'high'), grade, class_no, invite_code(6자리, unique) | 교사 1명당 1개 |
| `classroom_members` | classroom_id, student_id (unique), helper_subject(text, nullable) | 학생 소속. 학생 1명 = 학급 1개. `helper_subject`가 있으면 그 과목의 과제 작성 권한을 가진 과목도우미 |
| `posts` | id, classroom_id, author_id, type('notice'/'assignment'), subject(text, nullable — 과제만), title, body, due_date(nullable), link_url(nullable), created_at | 공지와 과제를 한 테이블로 |
| `duties` (Should) | classroom_id, weekday(0~6), student_names(text) | 요일별 청소 당번 |

- 시간표·급식은 **저장하지 않고** 나이스 API를 실시간 조회한다 (캐시 테이블 없음 — 해커톤 범위 축소)
- 챗봇 대화 기록도 저장하지 않는다 (새로고침 시 초기화 허용)
- RLS: `classrooms`·`posts`는 소속 학급 구성원만 select. 공지 작성·수정·삭제와 도우미 지정은 해당 학급 teacher만, 과제 작성·수정·삭제는 teacher 또는 `helper_subject`가 지정된 학생(본인 작성분)만

# 8. AI 기능

- **AI의 역할**: 학급 데이터 전용 질의응답 챗봇 (M9)
- **입력**: 학생의 자연어 질문 + 컨텍스트(해당 학급의 공지·과제 전체, 오늘 시간표·급식)
- **처리**: 시스템 프롬프트로 역할·범위를 제한("너는 ○반의 학급 도우미다. 아래 학급 데이터에 있는 내용만 답하고, 없는 내용은 '학급 정보에 없어요'라고 답해라") 후 Solar API 호출
- **결과**: 한국어 답변 텍스트. 날짜·마감일이 있는 항목은 날짜를 함께 표기
- **사용할 모델/API**: Upstage Solar API (chat completions). API 키는 서버 측(Edge Function 또는 프록시)에 두고 클라이언트에 노출하지 않는다

AI를 쓰지 않는 기능(공지 목록, 시간표 표시 등)에는 AI를 적용하지 않는다.

# 9. 기술 구성

현재 저장소 세팅을 그대로 사용한다.

- **Frontend**: Vite 8 + React 19 + TypeScript, Tailwind CSS v4, react-router v8, TanStack Query v5
- **Database / Backend**: Supabase (Postgres + RLS)
- **Authentication**: Supabase Auth (이메일)
- **Storage**: 사용 안 함 (파일 업로드 없음)
- **AI**: Upstage Solar API — Supabase Edge Function 경유 호출
- **External API**: 나이스 교육정보 개방 포털 (학교 검색 `schoolInfo`, 시간표 `misTimetable`/`hisTimetable`, 급식 `mealServiceDietInfo`)
- **Deployment**: Vercel

# 10. MVP 범위

## 이번 해커톤에서 반드시 구현
- 이메일 가입·로그인 + 역할 분기 (M1)
- 학교 검색 → 학급 생성 → 초대코드 발급 (M2)
- 초대코드로 학생 참여 (M3)
- 공지 등록(교사)과 목록·상세 (M4)
- 과목도우미 지정(교사)과 과제 등록(도우미) (M5, M6)
- 오늘의 홈 화면 — 시간표·급식·공지·임박 과제 (M7, M8)
- 학급 데이터 기반 AI 챗봇 (M9)

## 시간이 있으면 구현
- 청소 당번 (S1)
- 시간표 수동 입력 — 나이스 미제공 학교 대비 (S2)
- AI 오늘 할 일 요약 (C1)

## 이번에는 제외
- 서비스 관리자 역할과 교사 계정 승인
- 출결 기록·변경 이력
- 가정통신문 (공지로 통합)
- 나이스 데이터의 교사 검수·공개 워크플로 (조회 결과를 바로 표시)
- 인앱 알림·읽음 확인
- 계정 탈퇴·개인정보 보관 정책 화면
- 파일 업로드·과제 제출 관리
- 할일 탭·더보기 탭

> 데모의 성패는 기능 개수가 아니라 **교사 공지 → 도우미 과제 입력 → 학생 확인 → 챗봇 답변**이 끊기지 않고 이어지는가에 달려 있다. 위 제외 항목은 발표 시 "정식 버전 로드맵"으로 소개한다.

| 상황 | 처리 |
|---|---|
| 나이스에 시간표가 없는 학교 (실측 5개교 중 1개교 미제공) | 시간표 카드에 "학교에서 제공하지 않아요" 빈 상태 표시. 데모는 시간표 제공 학교로 진행 |
| 나이스 API 오류·타임아웃 | 해당 카드만 "불러오지 못했어요 · 다시 시도" 표시, 나머지 화면은 정상 렌더 |
| 잘못된 초대코드 입력 | "코드를 다시 확인해주세요" 안내, 재입력 가능 |
| 이미 학급이 있는 교사가 학급 생성 시도 | 기존 학급으로 이동시키고 생성 차단 |
| 도우미가 아닌 학생이 과제 작성 시도 | 작성 버튼 자체를 표시하지 않고, API 직접 호출도 RLS가 거부 |
| 챗봇에 학급과 무관한 질문 ("게임 추천해줘") | "학급 정보에 관한 것만 답할 수 있어요" 고정 응답 |
| Solar API 오류 | "잠시 후 다시 물어봐주세요" 안내, 앱은 정상 동작 유지 |
| 학급 미소속 학생이 홈 접근 | 초대코드 입력 화면으로 리다이렉트 |

# 12. 완료 기준

아래 문장이 전부 실제로 테스트되면 완성이다.

1. 교사 계정으로 가입해 "○○중학교"를 검색·선택하고 학급을 만들면 6자리 초대코드가 화면에 표시된다.
2. 학생 계정으로 가입해 그 초대코드를 입력하면 해당 학급에 참여되고 홈으로 이동한다.
3. 교사가 학생 한 명을 "수학 도우미"로 지정하면, 그 학생의 우리반 화면에 과제 작성 버튼이 나타난다.
4. 수학 도우미가 마감일이 있는 과제를 등록하면, 다른 학생 홈의 "마감 임박 과제" 카드에 그 과제가 과목·마감일과 함께 보인다.
5. 도우미가 아닌 학생 계정에는 과제 작성 버튼이 보이지 않는다.
6. 학생 홈에 오늘 날짜의 시간표와 급식이 나이스 데이터로 표시된다.
7. 학생이 챗봇에 "이번 주 과제 뭐 있어?"라고 물으면 도우미가 등록한 과제 제목과 마감일이 포함된 답변이 온다.
8. 챗봇에 학급과 무관한 질문을 하면 답변을 거절한다.
9. 학생 B 계정(다른 학급 또는 미소속)에서는 학급 A의 공지·과제가 조회되지 않는다.
10. 위 1~7을 배포된 Vercel URL에서 휴대폰 브라우저로 수행할 수 있다.

# 13. 개발 순서

1. **Supabase 스키마 + RLS**: `profiles`, `classrooms`, `classroom_members`(helper_subject 포함), `posts`(subject 포함) 테이블과 정책 생성. 가입 트리거로 `profiles` 자동 생성
2. **인증 플로우**: 가입(역할 선택)·로그인 화면, 로그인 후 역할·학급 소속에 따른 리다이렉트 (교사 무학급→학급 생성, 학생 무소속→초대코드)
3. **학급 생성**: 나이스 학교 검색 연동 → 학급 생성 → 초대코드 발급·표시
4. **학생 참여**: 초대코드 입력 → `classroom_members` 등록
5. **공지·과제 CRUD**: 공지 작성(교사), 과목도우미 지정 화면(교사), 과제 작성(도우미), 우리반 목록·상세 화면
6. **홈 화면**: 나이스 시간표·급식 실시간 조회 + 최근 공지·임박 과제 카드 (오류·빈 상태 포함)
7. **AI 챗봇**: Solar API 호출 Edge Function → 챗봇 화면 (컨텍스트 조립 + 범위 제한 프롬프트)
8. **배포·리허설**: Vercel 배포, 교사 1개·학생 2개(도우미/일반) 데모 계정으로 12번의 완료 기준 1~10 전체 리허설
9. *(남는 시간)* 청소 당번(S1) → 시간표 수동 입력(S2) → AI 오늘 할 일 요약(C1) 순서로 추가

각 단계는 이전 단계가 동작하는 상태에서 시작한다. 7번(챗봇)까지가 데모 필수 범위이고, 8번 리허설 시간을 반드시 남겨둔다.
